# Онлайн всередині APK — з 3.39

«Онлайн» відкриває Telegram-вхід у системному браузері **лише для авторизації**.
На початковій сторінці натисніть «Продовжити вхід». Після Telegram натисніть
«Увійти в застосунок», потім «Повернутися в МініКафе».
Каса, видачі та адміністрування надалі працюють всередині WebView APK.
Якщо браузер не повернув автоматично, відкрийте застосунок вручну й натисніть
«Перевірити вхід». Підтвердження діє 10 хвилин; після цього почніть заново.

Сесія пам’ятається на пристрої до семи днів. Права перевіряються сервером при
кожному запиті. При відкликанні доступу чи завершенні сесії потрібен новий вхід.
Вихід у вкладці сервера закриває онлайн-сеанс APK, не сеанс браузера.

## Межі режимів

- Онлайн завантажує актуальний захищений інтерфейс і базу сайту. Роль визначає
  Telegram-акаунт, а не маршрут чи кнопка. Нативний вибір фото, JSON-копій та
  збереження PDF/JSON підтримуються. Збереження через APK обмежено 20 МБ;
  для більших експортів скористайтеся браузером.
- Локальний режим, меню й база телефона залишаються окремими. Натискання
  «Онлайн» не запускає локальний сервер та не переносить дані. Ручне перенесення
  меню залишається окремою підтвердженою операцією адміністратора.
- Інтерфейс онлайн потребує інтернету. Локальні можливості не залежать від нього.

## Для розробника

`OnlineActivity` генерує 256-бітний випадковий proof. До браузера передається
тільки SHA-256 commitment у `/auth/app/start?challenge=…`. Браузерний сеанс
Telegram та явне CSRF-захищене підтвердження прив’язують його до користувача.
`POST /api/app/poll` отримує proof у тілі через HTTPS, одноразово видає **нову**
app-сесію й переносить підтверджену прив’язку права за номером телефону.
Дозволи перевіряються повторно перед видачею. URI `minicafe://online-complete`
не містить токена й лише будить застосунок; перехоплення URI не дає доступу.
Сесія браузера не копіюється, app-cookie записується нативно як HttpOnly/Secure.

Міграція `0008_app_login.sql` додає `app_links`. Telegram Client Secret та Bot
Token у APK не включаються; налаштування BotFather залишаються поточними.
При розгортанні спочатку міграція, потім Worker, потім APK з оригінальним підписом.
Для нового сервера app links із резервної копії слід анулювати разом із сесіями.

WebView обмежений HTTPS-origin сайту, сторонні HTTP-ресурси блокуються.
`CafeOnlineFiles` надає тільки збереження перевіреного PDF/JSON через системний
вибір файла; не читає локальну базу, не видає секретів і не приймає довільні шляхи.
Фото/JSON завантажуються через системний picker. Не замінюйте це небезпечним
JavaScript-інтерфейсом читання cookies/файлів або токеном у deep link.

Перевірки: `npm test`, `npm run test:api`, `tests/app-webview-ui.cjs` (макет
нативного збереження), повний `work/scripts/checks.py`. Вхід з реальним Telegram
і повернення на фізичному Android потребують перевірки власником; емуляція
Chrome/WebKit не доводить роботу Android intent/cookie provider на його телефоні.

`npm run test:app-login` у apps/online перевіряє справжнє надсилання форми
підтвердження в Chrome/WebKit проти локальної тестової D1. На HTML сторінках
app-входу зберігайте Referrer-Policy: same-origin: no-referrer перетворює Origin
форми на null і блокує підтвердження. Не послаблюйте серверні Origin/CSRF перевірки.
