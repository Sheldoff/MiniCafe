# Оплата на банку monobank

Онлайн-меню може приймати оплату на банку «Кафе». Android-local не змінюється.

## Робота гостя

Після оформлення сайт показує суму, посилання на банку і унікальний код `MC-…`.
Гість копіює код **без змін у коментар до переказу**, переказує точну суму в гривнях
та повертається до меню. Повернення з банку саме по собі не є підтвердженням.
Статус замовлення зберігається у цьому браузері після перезавантаження сторінки.
Не повторюйте переказ, якщо перевірка затрималась.

## Серверна перевірка

Worker Cron приблизно раз на хвилину читає виписку лише обраної банки через
офіційний personal API monobank. D1 обмежує звернення до виписки: не частіше
одного разу за 65 секунд. Webhook monobank не змінюється. Немає списання коштів
або доступу до карткових реквізитів платника через браузер.

Приймається лише завершений (`hold=false`) додатний платіж у гривнях з точною
сумою та точним кодом у полі `comment`, отриманий після створення замовлення.
Ідентифікатор банківської операції унікальний у D1; створення оплаченого замовлення,
зменшення залишків і відмітка виконаного платежу — одна атомарна транзакція.
Публічний статус доступний лише за випадковим 256-бітним токеном замовлення.
Номер картки, скриншот чи однакова сума не підтверджують оплату.

На оплату дається 30 хвилин. Пізня оплата або відсутність товару після платежу
отримують статус `review`. Адміністратор бачить їх у **Сервер → Оплати банки**.
Після перевірки наявності можна повторити передачу на приготування; новий платіж
для цього не потрібен. Якщо прийняти замовлення неможливо, повернення коштів
власник виконує вручну в банку. Автоматичного повернення немає.
Перекази без коду, з помилковим кодом/сумою чи кілька переказів з одним кодом
потрібно звіряти вручну у monobank; сайт не вгадує платника.

## Розгортання

Міграція `0009_mono_payments.sql` додає окремий платіжний журнал і блокування опитування.
Значення `MONO_TOKEN`, `MONO_JAR_ID`, `MONO_JAR_URL` — тільки Workers Secrets.
Токен і вибір банки зберігаються локально поза репозиторієм. Не друкуйте виписку,
баланс, токен або account ID у журнали/PR. API-тести — лише одноразова локальна D1.
Без усіх трьох налаштувань залишається попередній режим кодів для касира.
Перед вимкненням прийому платежів дайте завершитись очікуваним оплатам.

Cron переглядає останні 24 години для очікуваних платежів; після довшої перерви
потрібна ручна звірка банку. Повні банківські виписки у D1 не зберігаються.
Бізнес-backup не включає платіжний журнал: не використовуйте restore для відкату
живих оплат. Доступ банку й допустиме використання рахунку має забезпечити власник.

Перевірки: `npm test`, `node tests/mono-ui.cjs` (локальний сервер на 8795),
звичайні API/UI-регресії локального Worker. Нові SQLite-тести перевіряють
неправильну суму/валюту/код, hold, повторні операції, недоступність API,
прострочення, недоступний товар і атомарний відкат. Реальний платіж і фізичний
телефон не підміняються цими тестами; бойових тестових замовлень не створювати.

## Спрощена оплата (3.42 / онлайн 0.10.1)

Кнопка «Оплатити [сума]» копіює код і відкриває банку в цій вкладці з параметром
суми `a` у гривнях. Автозаповнення суми перевірено на сторінці банку без оплати.
Автозаповнення коментаря параметрами посилання не підтвердилося: сайт чесно
просить вставити скопійований код у коментар. Це обов’язкова дія для прив’язки.
Перехід не є підтвердженням оплати; серверні правила перевірки не змінені.
Якщо буфер обміну заборонений, перехід зупиняється, розкривається виділений код
і запасне посилання з готовою сумою. Детальні реквізити згорнуті за замовчуванням.
Після повернення з банку статус відновлюється з цього браузера. Для вже
підтвердженого або простроченого платежу основна кнопка оплати недоступна.
Персональний токен банку та webhook не змінюються. Реального тестового переказу
не виконували. Зміна входить у спільні гостьові assets APK та онлайн-версію.
