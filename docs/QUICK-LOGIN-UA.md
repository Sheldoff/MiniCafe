# Вхід без коду — 3.50 / 0.17.0

1. На ноутбуці відкрийте https://minicafe.minicafe.workers.dev/auth/login
   і натисніть **Вхід без коду · Telegram / QR**.
2. Камерою телефона відскануйте QR. Або натисніть **Відкрити Telegram**,
   якщо Telegram є на цьому ж пристрої.
3. У боті натисніть Start, звірте шість цифр із потрібним пристроєм
   і натисніть **Підтвердити вхід**. Ноутбук увійде автоматично.

Не потрібно писати /login, копіювати чи вводити код. QR діє 5 хвилин,
кожен запит одноразовий. **Скасувати** відхиляє вхід. Якщо час минув
або втрачено зв’язок, є кнопка **Створити новий QR-код**.
Вхід дозволений тільки акаунтам із уже наданою роллю. Підтверджуйте
лише свій запит із такими самими цифрами на своєму пристрої.

**Увести код вручну** залишається запасним способом. У відповідях /login
бот тепер має **Скопіювати код**. Код МініКафе відрізняється від кодів Telegram.

У APK кнопка онлайн-входу відкриває той самий браузерний сценарій.
Після підтвердження бота збережений захист browser→APK ще просить
**Увійти в застосунок**, потім **Повернутися в МініКафе**. Пристрій одержує
окрему сесію зі своєю роллю; локальний Wi-Fi-вхід не потребує Telegram.

## Розробка та розгортання

Міграція **0014_telegram_quick_login.sql** додає тільки тимчасові запити.
У D1 зберігаються хеші QR-ticket і незалежного browser proof, цифри звірки,
строк дії, стан і підтверджений Telegram ID. QR не містить секрету браузера
або сесії. Його генерує Worker через qrcode-generator 2.0.4 (MIT), без
зовнішнього QR-сервісу.

Start/підтвердження надходять лише через перевірений private webhook,
із перевіркою ID приватного чату, update_id і обмеженням частоти.
Підтвердження атомарне; права перевіряються і при підтвердженні, і при
створенні сесії. Чужий браузер не може забрати сесію, знаючи QR-ticket:
потрібні незалежні HttpOnly-cookie та CSRF/Origin початкового браузера.
Cookie сесії видає тільки сервер; JS бачить фіксований маршрут повернення.
Прихована сторінка не опитує сервер, після повернення перевіряє стан.

Наявний webhook раніше приймав тільки message. Після deploy потрібно:

```powershell
# З apps/online; ті самі Bot Token, secret, URL та IP override:
node configure-bot.mjs enable-callbacks
```

Цей режим перевіряє бота й чинну адресу, додає callback_query до allowed_updates,
зберігає max_connections/IP/оригінальний secret, не скидає чергу повідомлень.
Нових секретів і перевипуску токенів немає. Старі ручні коди/OIDC збережені.

Перевірки: npm test, локальна одноразова D1/API, npm run test:quick-login
проти локального HTTPS із тестовими bot secrets, як у BRAND-LOGIN-UA.md.
Chrome/WebKit використовують незалежні контексти телефона й ноутбука;
перевіряють автоматичний вхід і APK proof із роллю bar. ZXing окремо перевіряє
читання фактично відрендереного QR. Повний APK — checks.py без skip,
потім release.py. Реальні фізичні телефони/власний Telegram-акаунт цими
тестами не перевіряються. Робочі замовлення для тестів не створюються.

Telegram: https://core.telegram.org/bots/features#deep-linking ,
https://core.telegram.org/bots/api#callbackquery .
