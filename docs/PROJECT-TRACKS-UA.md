# Напрями MiniCafe — політика з 29.10.2026

## Одне сховище, два активні напрями

Не створюємо дві довгоживучі незалежні гілки local/online: вони розійдуться.
Обидва напрями живуть у main, задачі — у коротких task/* гілках через PR.

| Напрям | Канонічні джерела | Стан |
| --- | --- | --- |
| Спільний вебінтерфейс | work/frontend, work/cafe/frontend_build.py | Активний |
| Локальний Android | work/android, apps/local-android | Активний, робочий 3.36 |
| Онлайн | apps/online | Worker + D1, Telegram OIDC, персональні ролі; гостьова заглушка |
| Windows | work/desktop, частина work/cafe | Заморожено 3.36 |

apps/local-android — точка входу й конфігурація напряму; Java-джерела залишені
у work/android, щоб не ламати збірку переміщенням каталогів. apps/online — місце
майбутнього Cloudflare Worker, міграцій D1, тестів і конфігурації розгортання.
Не дублюй спільний UI вручну: використовуй існуючий канонічний збирач.

## Windows не оновлювати

Незмінний знімок усіх джерел попереднього випуску — гілка archive/windows-3.36,
створена з тега v3.36. Готовий EXE:
https://github.com/Sheldoff/MiniCafe/releases/tag/v3.36 .

Не змінювати Windows-обгортку, не встановлювати її залежності в стандартному
setup, не запускати Windows API/Tk/міграційні/EXE тести і не випускати EXE.
Після майбутніх змін спільного UI не перескладати Windows із main: для старого
стану використовувати зафіксовану гілку/тег. Сумісність старого EXE з майбутніми
API не гарантується і не повинна блокувати два активні напрями.

## Правила взаємодії

- Спільні зміни UX перевіряються на Android-local і, коли з’явиться, cloud-online.
- Telegram-вхід, сесії, ролі та гостьовий API — серверна частина онлайн-напряму.
- Локальні ключі, Wi-Fi, QR та Termux залишаються незалежними від Cloudflare.
- Онлайн-клієнт не показує кнопок запуску сервера телефона та Termux.
- Не відкривай локальний admin API публічно при перенесенні інтерфейсу.
- У UI чітко видно, який сервер/кафе зараз обрано. Чернетки й кеш ізольовані
  за ідентифікатором сервера, не тільки за URL.
- Бази локального і хмарного сервера окремі. Імпорт резервної копії явний;
  автоматичну двосторонню синхронізацію не реалізовувати без окремої задачі.

## Перевірки та релізи

Поточний checks.py: lint/format, Android APK, Java unit/API та Chrome/WebKit UI.
Жодної збірки/запуску Windows. --skip-build/--skip-ui — лише проміжна перевірка.
У summary.json profile=local-android; для релізу потрібен повний відповідний прогін.
release.py копіює лише APK та джерела; не перейменовує старий EXE новою версією.

Онлайн-тести й deploy розташовані окремо під apps/online. Локальна зміна не повинна
автоматично витрачати ліміти розгортання Workers. Тестові бази відокремлені від
production. Не підключай чужий наявний Worker або D1 цього акаунта.

Cloud-проєкт: minicafe.minicafe.workers.dev, Worker minicafe, окрема D1 minicafe-db.
Акаунт і ресурси зафіксовані у apps/online/wrangler.jsonc. Квоти Free спільні для
акаунта. Локальні OAuth secrets — у виключеному .wrangler-auth; вони також
виключаються з вихідних ZIP. Відкритий доступ є тимчасовим тестовим режимом;
Telegram-вхід і гостьовий окремий API — наступна задача. Автодеплою немає.
