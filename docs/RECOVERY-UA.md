# Відновлення без старого ПК

Код та історія: https://github.com/Sheldoff/MiniCafe

Приватне сховище: https://github.com/Sheldoff/MiniCafe-Recovery
Доступ потрібен саме до обох репозиторіїв. У приватному — тільки зашифровані
знімки та інструкція, а не відкриті паролі. Репозиторій не повинен ставати публічним.

## Обов’язково зберегти окремо

Власнику потрібні доступи до GitHub, Cloudflare, Telegram/BotFather і файл
`MiniCafe-Recovery-Key.json`. Ключ розшифрування **не зберігається на GitHub**.
Початкове місце на старому ПК: `outputs/recovery-private/MiniCafe-Recovery-Key.json`.
Збережіть його поза ПК, наприклад як захищене вкладення в менеджері паролів.
Без цього файла зашифрований знімок не відкрити. Не надсилайте ключ у чат.

## Вміст знімка

- Оригінальні APK-keystore, паролі, очікуваний сертифікат.
- Client Secret Telegram Login, Bot Token, webhook secret у приватному JSON.
- SQL-експорт усієї онлайн-D1: меню, фото, історія, права й службові таблиці.
- Знайдена на ПК локальна база Windows та її ключ доступу.
- Git bundle з історією та гілками; оригінали восьми зображень базового меню.

Це знімок на вказаний у назві момент, **не постійна синхронізація** баз.
Дані телефона сюди не потрапляють автоматично: експортуйте актуальну резервну
копію з APK та додайте її до наступного зашифрованого знімка. Тестові бази,
завантажувані SDK/node_modules, кеші й OAuth-сесії GitHub/Wrangler не копіюються.
На новому ПК увійдіть у GitHub/Cloudflare заново. APK/EXE також є в GitHub Releases.

## Розшифрування на новому ПК

1. Клонуйте обидва репозиторії й отримайте ключ у власника окремим способом.
2. Встановіть Python і `cryptography==50.0.2`.
3. Розшифруйте актуальний знімок у **порожній приватний каталог**:

```sh
python work/scripts/recovery_archive.py unpack --archive <snapshot.mcbackup> --key-file <MiniCafe-Recovery-Key.json> --folder <private-restored-folder>
```

Шифрування AES-256-GCM перевіряє автентичність; додатково звіряються SHA-256
кожного файла. При помилці не намагайтесь обходити перевірку чи змінювати ключ.

4. `credentials/minicafe-signing.jks` і `signing.local.json` поверніть до
   `work/android/`; `credentials/telegram.local.json` — до
   `apps/online/.env.telegram.local.json`. Не комітьте ці файли.
5. Прочитайте актуальні AGENTS.md та DEPLOY-UA.md, перевірте підпис APK.
   Новий ключ замість оригінального не генеруйте.
6. SQL відновлюйте лише за потреби у **нову порожню D1**. Не імпортуйте його
   автоматично поверх робочого сайту. Експорт містить чутливі дані та auth-таблиці;
   якщо піднімаєте інший сервер, анулюйте відновлені сесії та одноразові дозволи.
7. Якщо звичайного репозиторію немає, `git clone source.bundle MiniCafe` відновить
   збережену історію. Потім підключіть origin та отримайте новіші коміти за наявності.

## Наступні знімки

Після істотних змін даних/секретів оновлюйте зашифровану копію. Не кладіть
recovery key у payload чи репозиторій. `recovery_archive.py pack` використовує
окремий ключ та новий випадковий nonce; завжди перевіряйте round-trip перед push.
Шифрування не замінює контролю доступу до приватного сховища.
