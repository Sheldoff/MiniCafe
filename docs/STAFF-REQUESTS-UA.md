# Заявки на доступ через Telegram

На сайті: **Сервер → Доступи працівників → Посилання на заявку**.
Посилання відкриває `https://t.me/minicafe_loginbot?start=apply`.

Людина натискає Start і «Подати заявку». Можна замість цього натиснути
«Подати заявку з номером» і передати власний контакт. Чужий контакт не приймається.
Без номера заявка також працює — після схвалення доступ прив’язується до Telegram ID.

У працівниках під списком з’являється блок «Заявки», якщо є нерозглянуті записи.
Він оновлюється раз на 30 секунд лише на відкритій видимій сторінці. Логотип
«МініКафе» в бічному меню також оновлює дані, не стираючи форму нового доступу.

- «Докладніше»: ID, ім’я/прізвище, username, мова, доступні позначки Premium,
  номер лише після добровільного надсилання, біо/дата народження/фото, якщо
  Telegram повернув їх боту. Розділ «Усі дані Telegram» містить фактично
  отримані поля профілю. Приховані Telegram дані не вигадуються; листування
  та закріплені повідомлення не зберігаються як інформація про людину.
- «Прийняти»: адміністратор вибирає роль; лише після підтвердження сервер
  надає доступ. Користувач отримує повідомлення й посилання на вхід.
- «Відхилити»: доступ не надається; можна подати нову заявку в межах короткого
  обмеження частоти дій. Стара форма не може схвалити нову версію заявки.

Надана роль редагується/відкликається/видаляється у блоці працівників. Власники
з ADMIN_TELEGRAM_IDS залишаються окремими: через заявки не можна отримати admin.

## Налаштування бота для розробника

Client Secret Telegram Login і Bot Token — різні секрети. У приватному
`apps/online/.env.telegram.local.json` зберігається TELEGRAM_BOT_TOKEN.
configure-bot.mjs генерує окремий TELEGRAM_WEBHOOK_SECRET, перевіряє getMe та
відмовляється змінювати webhook іншого застосунку.

З apps/online:

```sh
node configure-bot.mjs upload
# Застосувати міграції та опублікувати Worker через cf.ps1.
node configure-bot.mjs register
```

Якщо DNS Telegram тимчасово не визначає workers.dev, скрипт перевіряє
публічні IPv4 сервера через HTTPS із перевіркою сертифіката та використовує
офіційний параметр setWebhook.ip_address. Повторний register зберігає робочу
адресу; якщо вона перестає працювати, перебирає актуальні перевірені адреси.

Webhook: `/api/telegram/webhook`. Приймає тільки приватні повідомлення із
правильним X-Telegram-Bot-Api-Secret-Token; повторні update_id відсіюються,
дії обмежені за користувачем. Заявка сама по собі не надає прав. Список та
рішення доступні лише адміністратору, зміни вимагають CSRF й правильного Origin.
Секрети й URL з Bot Token не журналюються та не включаються в Git/архіви.
