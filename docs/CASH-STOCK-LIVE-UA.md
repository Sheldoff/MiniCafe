# Залишки по касах, черги та «Онлайн» — 3.55 / online 0.22

У вебкаталозі на ширині до 700 px товар знову займає компактний рядок. Це стосується також вебрежиму всередині APK; локальні картки APK залишаються. У редакторі всіх активних версій прибрані верхні назва, опис і кнопка «До списку». Залишаються «Зберегти», «Закрити редактор» та системна кнопка «Назад».

## Один залишок, кілька кас

Якщо створено додаткові каси, під загальною кількістю з’являється розподіл по касах у порядку бічного меню. Спочатку вкажіть загальну невід’ємну кількість, зокрема отриману з калькулятора. Наприклад, для 20 порцій введіть 7 на першій касі — наступна автоматично отримає 13. Якщо на ній ввести 5, третя отримає 8. Сума розподілу має дорівнювати загальному залишку; сервер перевіряє це незалежно від браузера. Нуль повністю приховує товар на відповідній касі й забороняє продаж через API, включно з орієнтовним режимом.

Продаж одночасно зменшує загальний залишок і кількість своєї каси. Скасування повертає кількість тій самій касі; якщо її вже видалено, повернення надходить основній касі. Повторний запит оплати не списує товар удруге. Скасування видачі порції не є скасуванням продажу й залишок не змінює.

Якщо загальна кількість змінюється калькулятором або старим API-клієнтом, наявний розподіл зберігається зліва направо в межах нового залишку, решта надходить останній касі. Нова каса для вже розподіленого товару починає з нуля; при видаленні або зміні типу каси загальний залишок не губиться, а перерозподіляється між рештою кас. Без числового залишку розподіл вимкнений, діє попередній необмежений режим. Нерозподілені старі товари зберігають попередню загальну кількість до явного редагування.

Редактор передає початковий стан кількості: якщо за час редагування відбувся продаж або інший перерозподіл, сервер відхиляє застаріле збереження. Закрийте редактор і знову натисніть сам товар, щоб отримати актуальний залишок. Дані розподілу зберігаються в резервній копії та після перезапуску. Звичайне перенесення лише меню між серверами переносить загальну кількість, а не прив’язки чужих локацій.

Публічне онлайн-меню й автоматична онлайн-оплата працюють з основною касою; для них враховується її доступний залишок. Внутрішні значення інших кас не потрапляють у публічний каталог. Працівник із доступом до окремої каси отримує тільки її частину розподілу.

## Маршрути без дублювання типів

Напої направляються тільки бариста, їжа — тільки на видачу їжі. З обраних у налаштуваннях каси напрямків використовуються тільки черги відповідного типу. Якщо потрібного типу не обрано, використовується основний бариста або основна видача, щоб замовлення не загубилося. Це правило діє також для старого режиму «все на одну видачу».

Кілька бариста або кілька видач одного типу бачать спільне виконання позиції: видача на одній точці одразу враховується на інших. Чек, оплата й списання залишку залишаються одними. Старі активні позиції з помилковими напрямками також фільтруються за початковим типом товару; фінансова історія та вже видані порції не переписуються.

У бічному меню баристи окремі кольорові цифри рахують порції напоїв від кожної каси: одне замовлення з трьома кавами дає 3. Нулі приховані; підказка містить назву каси, кількість замовлень і порцій. Лічильник видачі зберігає попередній підрахунок порцій. Для порожніх черг використані SVG coffee/utensils з уже наявного набору Lucide. На сторінці локацій кнопка створення стоїть поруч із заголовком, а в рядках — іконка типу, назва, потім колір.

## Статистика → Онлайн

Третя вкладка показує тільки поточну відкриту сесію, незалежно від вибраного історичного періоду. Доступна адміністраторам. Автооновлення — кожні 15 секунд, поки сторінка видима; є ручне оновлення та час останніх успішних даних. Після завершення сесії старі графіки прибираються.

Показники: виручка, сума після витрат, кількість замовлень і подарунків, середній чек без подарунків, порції та замовлення в черзі, найдовше очікування цієї сесії. Графіки: виручка й кількість замовлень у часі, готівка/картка, виручка окремих кас, популярні позиції за порціями. Крок часових графіків адаптується до тривалості сесії; є таблиця точних значень. Суми узгоджені зі звичайним звітом: скасування позиції не реєструє повернення оплати автоматично.

При мережевій помилці видно останні дані з попередженням; при 401/403 фінансові показники прибираються. Відкритий блок даних графіків зберігається при оновленні. Графіки працюють без сторонніх бібліотек чи зовнішніх сервісів, включно з локальним APK.

## Реалізація й перевірки

`stock_by_cash` зберігається в JSON товару; нової схеми D1, міграцій, секретів або зміни webhook немає. Старі резервні копії без цього поля підтримуються. Windows залишається замороженим. Для нового обліку використовуйте онлайн 0.22 / APK 3.55.

Перевірки: `cash-stock-live.test.js`, `cash-stock-live-api.mjs` на одноразовій локальній D1, Java `CashStockLiveTest`, Chrome/WebKit `work/tests/ui/cash-live.cjs` для онлайн й Android. Повний випуск потребує `checks.py` без пропусків, оригінального підпису APK та окремого Cloudflare deploy. Фізичні телефони не використовувалися; тестових замовлень чи restore на production не виконується.
