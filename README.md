# МініКафе 3.36 — структура та перевірки

## Поточні напрями розробки

- **[Локальний Android](apps/local-android/README.md)** — активний APK-сервер,
  Wi-Fi/точка доступу та інтернет через Termux.
- **[Онлайн Cloudflare](apps/online/README.md)** — окремий напрям для Workers,
  D1, Telegram-входу та гостьових замовлень. Реалізація ще не розпочата.
- **Windows 3.36 — заморожено**: готовий EXE у Releases, незмінні джерела
  у гілці `archive/windows-3.36`. Нові EXE не збираються й не тестуються.

Детальні правила: [docs/PROJECT-TRACKS-UA.md](docs/PROJECT-TRACKS-UA.md).
Історичні згадки Windows нижче не є завданням продовжувати його підтримку.

Один інтерфейс і одне серверне ядро для Android та Windows. Тестові дані ізольовані від робочої бази кафе. Для продовження в новому чаті спочатку прочитайте START-HERE-UA.md та PROJECT-CONTEXT.json.

## Структура

- `work/frontend/` — єдині HTML/CSS/JS-джерела, порядок складання в `manifest.json`. Модулі: каса, оплата, видача, редактор, статистика, калькулятор, маршрути, мережа, анімації.
- `work/cafe/frontend_build.py` — детерміноване складання інтерфейсу. `assets/index.html` є результатом, не редагуйте його вручну.
- `work/android/src/ua/minicafe/mobile/` — спільні `CafeStore`, `CafeHttpServer`, `CafeStats`, `ImageStore`, `AccessControl`, PDF та окремі Android-екрани/служба.
- `work/desktop/DesktopServer.java` — запуск того самого ядра на Windows.
- `work/cafe/app.py`, `desktop_engine.py` — вікно сервера Windows, QR/посилання, резервні копії й одноразове перенесення старої SQLite.
- `work/tests/unit/java`, `tests/api`, `tests/ui` — актуальні тести. `work/tests/results/` — ізольовані результати прогонів.
- `work/scripts/` — актуальні команди перевірки, збірки й випуску.
- `work/archive/` — старі реалізації/сценарії для довідки; не беруть участі в збірці.

## Дані та сумісність

Android зберігає JSON у внутрішньому каталозі застосунку. Windows — у `%LOCALAPPDATA%/MiniCafe`. Фото зберігаються в сусідньому `cafe-data.json.images/` під SHA-256; JSON містить посилання, а не Base64. Перенесення старих фото виконується при відкритті бази: спочатку надійно записуються фото, потім атомарно перемикається JSON. Попередній JSON лишається в `.bak`; невикористані фото не видаляються автоматично, щоб не пошкодити резервне відновлення.

Експорт резервної копії — один JSON із вбудованими фотографіями. Він переноситься між телефонами та Windows. Не переносіть тільки робочий `cafe-data.json` без каталогу фотографій. Для відновлення використовуйте кнопку резервної копії.

При першому запуску нової Windows-версії стара `cafe.sqlite3` копіюється в `cafe-before-3.28.sqlite3`, а дані переносяться в нове спільне ядро. Початкова SQLite не видаляється. Старі чеки без записаного способу оплати залишаються з невідомим способом, суми не вигадуються. Старий EXE не бачить нових змін нового ядра.

Робочий формат з атомарним JSON залишено: фото вже винесені, великі звіти рахуються поза блокуванням записів, історія має пагінацію. Перехід на SQLite, SSE/WebSocket та CameraX був умовним наступним кроком аудиту; він не потрібен для цих оптимізацій і не виконується без потреби. Дані вимірювань лежать у `outputs/MiniCafe-3.28-benchmark.json`; це Windows, не оцінка швидкості телефона.

## Доступ

- Повний доступ (admin): власник, старий ключ збережений для сумісності.
- Видача (service): каса, бариста й видача їжі; без звітів, редактора меню та налаштувань.
- Тільки каса (cash): приймання замовлень.
- Тільки бариста (bar): напої й дії своєї черги, без оплати/їжі.
- Тільки видача їжі (delivery): їжа й дії своєї черги.

Права перевіряються сервером, зміна #bar на #menu їх не підвищує. «Відкликати посилання персоналу» змінює ключі чотирьох ролей, власника не відключає. Посилання власника передавайте лише довіреним адміністраторам.

## Збірка

Потрібні Python 3.10+, Node 22.13+, JDK 17, Android SDK platform 35/build-tools 35.0.0. У поточному робочому середовищі SDK/JDK є в `work/android-tools`. Параметри `MINICAFE_PYTHON`, `JAVA_HOME`, `ANDROID_HOME` дозволяють інші шляхи. Залежності Java перевіряються за SHA-256. `npm ci --prefix work/tooling` ставить зафіксовані інструменти перевірки; Playwright задається через `PLAYWRIGHT_MODULE`, Chrome — за потреби через `CHROME_EXECUTABLE`. Для WebKit потрібні браузерні файли Playwright.

```powershell
python -X utf8 work/scripts/checks.py
```

Це перевіряє синтаксис/повторні оголошення/невідомі глобальні змінні та форматування, запускає 17 Java-наборів, контракт API, сценарії Chrome/WebKit, збирає спільний сервер Windows, повторює контракт, перевіряє перенесення SQLite та створення вікна Tk/QR, потім збирає APK й EXE. `--skip-build` пропускає фінальні збірки, `--skip-ui` — браузерні перевірки; вони не є повним випускним прогоном.

```powershell
powershell -ExecutionPolicy Bypass -File work/android/build.ps1 -PythonExe <python.exe>
powershell -ExecutionPolicy Bypass -File work/scripts/build_desktop.ps1 -PythonExe <python.exe>
python -X utf8 work/scripts/release.py --version 3.28
```

APK збирається щоразу в новому каталозі. Релізна збірка вимагає оригінальний `minicafe-signing.jks` та перевіряє `signing-cert.sha256`. Новий ключ автоматично не генерується. Паролі читаються з середовища `MINICAFE_STORE_PASSWORD`/`MINICAFE_KEY_PASSWORD` або незавантажуваного в архів `signing.local.json`. Ключ і паролі не входять у вихідний ZIP. Без них збірка власного сумісного оновлення неможлива; резервну копію ключа треба зберігати окремо.

Для EXE комплектується мінімальне Java-середовище, тому встановлювати Java користувачу не потрібно. EXE буде більшим за старий випуск; APK не містить desktop runtime.

## Межі перевірки

Автотести перевіряють функціональні сценарії й міграції на ізольованих файлах. Вони не замінюють перевірку фонової роботи, камери, системних жестів і енергозбереження на фізичному Android. При оновленні встановлюйте APK поверх наявного без видалення; потім перезапустіть сервер та оновіть сторінки інших пристроїв.

## Зміни 3.30

Одночасні читання стану об’єднуються в один запит. Якщо під час читання сервер підтвердив запис, виконується одне наступне читання; застаріла відповідь не застосовується. Тайм-аут охоплює також отримання тіла JSON. Автоматичних повторів записів немає.

HTML має ETag від вмісту і private/no-cache: браузер перевіряє версію при відкритті, незмінений інтерфейс отримує 304. Стиснення gzip JSON/HTML та незмінені API-права перевіряються контрактом обох серверів. Фото та дані не отримують нових довгих кешів.

Підтверджена сервером видача відображається локально навіть при невдалому наступному читанні; після відновлення зв’язку стан сервера залишається остаточним. Зміни наявності оновлюються у видачі незалежно від змін замовлень. Застаріла помилка історії не перекриває актуальну відповідь; розгорнуті записи зберігаються при оновленні того самого періоду.

Перервані переходи каси прибирають попередні копії панелей; повторне встановлення вже відкритої вкладки не скасовує чинний перехід. Перерваний пошук товарів очищає тимчасове обрізання; перемикання теми зберігає рух індикатора вкладки. Повернення видачі не перемальовує чергу повторно після своєї анімації. Регресії мережі та повторних натискань: work/tests/ui/network-motion.cjs.

## Зміни 3.31

Перемикання теми: 107 мс замість 320 мс; іконка 93–107 мс. Плавно змінюються фони та межі, без каскаду анімованого успадкованого кольору тексту й важких тіней.

Нативне підключення Android: центрована колонка до 840 dp, окремі картки сервера, Wi-Fi, інтернету, іншого сервера та копій. Termux: компактне перше налаштування; три основні кроки — запуск, адреса, підключення працівників. Команди можна копіювати разом із відкриттям Termux; адреса має вставлення/очищення; дії на планшеті стають парами кнопок. QR має обмежену ширину. Адреси та ролі зберігаються при перевідтворенні екрана.

Планшетний CSS спільний для браузера та APK WebView: до 999 px каса показує широкі вкладки, від 1000 px — дві колонки. Дотикові кнопки від 44 px, більші фото й назви; редактор при вузькому планшеті стає одноколонковим. Перевірки 768×1024, 800×1280, 1024×768, 1280×800 у Chrome/WebKit, також із нативними прапорцями UI (це моделювання мосту, не запуск Android емулятора). Фізичний планшет/Android-емулятор не підключалися.

## Зміни 3.32

Єдиний цикл openOrderDialog/closeOrderDialog: усі власні діалоги з’являються за 140–160 мс та закриваються за 120 мс. Повторне відкриття прибирає попередній діалог без дублювання id; під час закриття його кнопки недоступні. Escape та жест назад користуються тим самим циклом.

Перехід сторінки запускається один раз після даних сервера. Приховані або вперше створені списки не анімуються з виміряної нульової висоти: перший показ належить сторінці. Android додає мітку MiniCafeAndroid до User-Agent до завантаження, тому перший показ WebView не накладається на веб-анімацію. Нові рядки й подальші зміни зберігають власні переходи.

Підказки, повідомлення, попередження про зв’язок та порожня черга мають переходи. Закриття/відкриття можна змінити на протилежне до завершення; тимчасове overflow прибирається. За висувним меню немає важкого backdrop-filter.

CafeQr створює QR поза головним потоком Android, зберігає до чотирьох готових bitmap у пам’яті та ігнорує застарілі запити до ImageView. Готовий QR з’являється плавно. Формування посилання, ключі та кодування QR залишилися попередніми.

Нові UI-перевірки appearances.cjs: перший вхід без кешу в касу, калькулятор, меню, історію, бариста; моделювання нативного першого показу; усі власні діалоги; швидкі заміни, назад/Escape; підказки й повідомлення; режим зменшеної анімації. Нативний QR перевірено компіляцією та аналізом потоків; фізичний Android-пристрій не підключався.


## Зміни 3.33

Бариста й видача їжі використовують спільний перехід появи замовлення, повернення та порожньої черги: 220 мс, opacity/translateY і одна крива плавності. Виправлено пропуск анімації порожньої черги після видачі останнього замовлення. При першому відкритті залишається лише перехід усієї сторінки, без подвійної появи вкладених блоків.

Під час видачі вхідні рухи карток зупиняються зі збереженням їхньої поточної позиції; нова анімація не конкурує з попередньою за transform. Після завершення очищаються тимчасові розміри контейнера. Повернення не запускає порожні анімації нерухомих замовлень.

У масових списках редактора/калькулятора нові рядки з'являються через opacity/transform без покадрової зміни height/padding/border. Розміри рядків вимірюються одним проходом до запуску анімацій, також у кошику. Прибрані постійні will-change та застаріла перекрита CSS-анімація видачі. Одиничні розгортання й згортання зберігають зміну висоти там, де вона потрібна для плавного руху вмісту.

У нативному вікні інтернет-підключення швидкі зміни видимості завершують попередній перехід; зміна розмірів і прозорості виконується одночасно. Автотест queue-motion.cjs звіряє обидві видачі, повернення, останнє замовлення, видачу під час появи, очищення тимчасових стилів, зменшену анімацію та швидкі зміни великих списків. Вимірювання FPS на фізичному Android не проводилося.


## Зміни 3.34

Виправлені світлі фони інтерактивних рядків товарів і додаткових витрат у темній темі. Стани наведення, утриманого натискання та клавіатурного фокусу використовують темні поверхні й узгоджений видимий контур. Межі рядків товарів також підпорядковуються темі.

Перевірка контрасту theme.cjs охоплює значення та підказки полів вводу, редагування наявного товару, усі інтерактивні стани рядків товарів і витрат у двох темах. Автотести виконуються у Chrome та WebKit. Фізичний Android не використовувався.

Порожній попередній перегляд зображення має темний фон; фон фото узгоджується з наявністю картинки й відновлюється разом із чернеткою. У світлій темі підсилено контраст опису товару й кнопки видалення.


## Зміни 3.35

Підключення Android: «Підключити інший пристрій», «Підключитися до іншого сервера» й «Меню та резервні копії» відкривають окремі екрани з поверненням, як Termux. Усі чотири кнопки переходу мають повну ширину та висоту 64 dp. Адреса, роль і вибраний екран зберігаються при перевідтворенні Activity. Розгортання першого налаштування й допомоги Termux змінює реальну зайняту висоту, тому сусідні блоки рухаються і при закритті; повторне натискання змінює напрямок від поточної висоти.

Прибрано верхні зайві заголовки й окрему картку стану сервера в інтернет-підключенні. «Почати роботу» розташовано внизу блоку підключення працівника, із золотим акцентом. Додано посилання на офіційну сторінку Termux у F-Droid.

Порядок доступів на Android/Windows: Повний доступ; Видача; Тільки каса; Тільки бариста; Тільки видача їжі. Нова роль service («Видача») дозволяє касу, обидві черги, повернення видачі й керування наявністю; сервер забороняє їй звіти, меню, витрати, резервні копії та керування ключами. Міграція додає лише новий ключ, зберігаючи старі посилання; відкликання змінює всі ключі персоналу, зберігаючи власника. Окремий Java-тест перевіряє дозволи через HTTP і збереження ключів.

Бічне меню: «МініКафе» оновлює дані без закриття меню, індикатор з’являється одразу, залишається при помилці й зникає після успішного зв’язку. Повторна команда закриття не зриває завершення анімації; зайве натискання на щойно відкритий фон ігнорується під час відкриття. Кнопки «Розробник» і «Сервер» розташовані внизу. У браузері «Сервер» показує адресу й перевірку зв’язку; в APK відкриває налаштування. «Розробник» відкриває Telegram та банку monobank лише після натискання. Android відкриває ці два посилання зовнішнім застосунком через перелік дозволених URL.

Автотести navigation.cjs: Chrome/WebKit, швидке відкриття/повторне закриття/розворот руху, оновлення з відсутністю мережі й відновленням, збереження кошика, доступні вкладки для всіх ролей. Нативні екрани перевірені компіляцією APK; перевірка жестів і анімацій на фізичному Android ще потрібна.


## Зміни 3.36

Плавний перехід до сервера: спочатку закривається бічне меню, потім відкривається екран; Android залишає вихідний WebView живим до завершення переходу Activity. Повторне натискання не створює кілька переходів. При відкритті меню дотиком фокус не ставиться на МініКафе; відкриття клавіатурою фокусує кнопку закриття. Розробник має виразний активний стан в обох темах. Додано номер картки 4441111056584349 з копіюванням через браузерний буфер/HTTP fallback або нативний буфер Android.

Каса до 999 px: свайп вліво відкриває замовлення, вправо повертає меню через існуючу анімацію панелей. Свайп не додає й не віднімає товарів. Ввід, окремі кнопки, вертикальний скрол, короткі/скасовані/багатопальцеві жести й довге натискання зберігають поведінку; краї екрана залишені для системного назад. На широких екранах залишаються дві колонки. Новий модуль cash-swipe.js реєструється перед старими hold-слухачами. Тести охоплюють Chrome/WebKit та реальні CDP-touch події Chromium.

Архів MiniCafe-3.36-source.zip містить канонічні джерела Android/Windows/браузера, фото/шрифт/Java-бібліотеки, тести, lock-файли та setup_dev.ps1. START-HERE-UA.md, PROJECT-CONTEXT.json і NEXT-CHAT-PROMPT-UA.txt пояснюють контекст новому чату; SOURCE-FILES-SHA256.json перевіряє вміст. Секрети підпису APK й робочі дані не включені. Старий MiniCafe-Android-source.zip лишається сумісним псевдонімом нового архіву.
