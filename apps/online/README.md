# MiniCafe Online — Cloudflare

Стан: Telegram-вхід персоналу — https://minicafe.minicafe.workers.dev/admin .
Worker сам обробляє API, D1 зберігає дані. Телефон і Termux не потрібні.
Гості бачать публічне меню та отримують тимчасові коди для каси.
Інструкція: docs/GUEST-CODES-UA.md у корені репозиторію.
Доступ персоналу перевіряється сервером; публічне API не надає прав керування.
Адміністратори 600810855 і 1402380598 можуть надавати/відкликати ролі працівників.
Запуск, розгортання, перевірки та обмеження: [DEPLOY-UA.md](DEPLOY-UA.md).

## Запланована структура

- src/ — Worker, маршрути, права, сесії, Telegram Login/Mini App validation.
- migrations/ — версійована схема D1.
- tests/ — логіка, API, права, ідемпотентність, гостьові замовлення.
- wrangler.jsonc — окреме ім’я сервісу, assets із спільного UI, D1 binding.
- package.json/lock — зафіксовані залежності.

Конфігурація й ресурс D1 створені в окремому погодженому акаунті; секрети
локально ізольовані та не потрапляють у Git. Deploy-on-push не увімкнений:
публікація виконується явно через cf.ps1 після перевірок.

## Наступний етап (ще не реалізований)

1. Спільний дизайн/екрани й окремий серверний адаптер API вже реалізовані.
2. Telegram OIDC + PKCE, серверні ролі й відкликання вже реалізовані.
   Перший випадковий користувач не стає адміністратором.
3. Гості — окреме посилання/QR без обов’язкового Telegram; лише публічне меню,
   створення й перегляд власного замовлення, без робочої статистики чи admin API.
4. Адміністратор може вимкнути онлайн-замовлення; перевірка при записі на сервері,
   включно з уже відкритими сторінками. Прийняті замовлення не видаляються.
5. Захист від спаму, ліміти, серверний розрахунок цін, доступність позицій,
   унікальні request ID та захист від повторних замовлень.
6. Онлайн-замовлення не дорівнює онлайн-оплаті: еквайринг не входить до задачі.
7. D1: транзакційні операції/пакети, міграції, backup/export, індекси й економне
   оновлення черг. Не переносити весь локальний JSON при кожному запиті.
8. Фото — окрема обґрунтована стратегія; не підключати платне сховище автоматично.

Публічна адреса workers.dev; Windows/Android не повинні бути запущені для роботи
хмарної версії. При втраті інтернету хмарні записи недоступні; локальний режим
має окрему базу. Двосторонньої автоматичної синхронізації на цьому етапі немає.

Secrets (Telegram bot token/OIDC client secret тощо) — тільки Cloudflare secrets.
Публічний GitHub не повинен містити їх або робочі бази.
Не змінювати інший існуючий проєкт користувача в Cloudflare.
