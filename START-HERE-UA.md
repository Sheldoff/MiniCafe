## Що робить застосунок

Локальне мінікафе: каса формує замовлення з ім’ям/номером гостя, ціною й оплатою; напої надходять бариста, їжа — на окрему видачу. Сервер працює на телефоні Android або ноутбуці Windows. Клієнти — APK/WebView чи звичайний браузер, зокрема iPhone. Wi-Fi/точка доступу працюють локально; Cloudflare Quick Tunnel через Termux дає HTTPS-доступ до сервера телефону. Хмарного облікового запису, Google-входу чи онлайн-еквайрингу немає.

Меню, фото, категорії, ціни, обробник, видимість, наявність та орієнтовний залишок редагуються. Каса підтримує коментарі до позицій, зміну ціни конкретної позиції в замовленні, подарунковий чек, змішану оплату, решту. Видача відмічає кожну порцію окремо й повертає останню дію. Сесії, PDF-звіти, витрати, калькулятор розподілу закупівлі та резервні копії вже реалізовані.

## Де змінювати код

- work/frontend/ — канонічні HTML/CSS/JS. manifest.json визначає порядок класичних inline-скриптів; збірник work/cafe/frontend_build.py створює один HTML. Не редагуйте згенеровані index.html вручну. Функції глобальні, тому lint_frontend.cjs перевіряє їх разом.
- work/android/src/ua/minicafe/mobile/ — Java-ядро спільного HTTP-сервера, дані, права, PDF; також Activity/Service Android.
- MainActivity — WebView, камера/файли/PDF/буфер обміну/переходи до сервера. HostActivity — основний екран сервера та підекрани. InternetActivity — Termux. CafeUi/CafeDisclosure/CafeQr/CafeRoles — спільні нативні компоненти.
- work/cafe/app.py та desktop_engine.py + work/desktop/DesktopServer.java — Windows-обгортка спільного ядра. EXE має власне мінімальне Java-середовище.
- work/tests/ — регресії Java, API та Playwright. У робочу базу користувача вони не пишуть.
- work/scripts/ — збірка, перевірки, архівування; work/tooling/package-lock.json фіксує npm-залежності.

## Незмінні правила сумісності

1. Гроші на сервері — цілі копійки. Ввід для зручності редагує гривні, відображення може мати копійки. Ціни меню зазвичай кратні 5 грн.
2. Подарункові замовлення мають нульову оплату й не входять у найменший/середній чек. Їхні кількості зберігаються.
3. Виручка після витрат = продажі мінус витрати. Додаткові витрати об’єднуються у звіті за нормалізованою назвою, але зберігають окремі записи для редагування.
4. Редагування/приховування меню не переписує історичні назви й ціни замовлень. Оновлення коду не повинно перезаписувати меню користувача базовим.
5. Фото зберігаються поза основним JSON за SHA-256. Для перенесення потрібен штатний експорт резервної копії з фото, а не лише копіювання cafe-data.json.
6. Записи атомарні, замовлення ідемпотентні за request. Не повторюйте POST автоматично при втраті зв’язку.
7. Однакове ядро для Android/Windows. API-контракт, обмеження прав, ETag/304/gzip та порядок читання після запису мають зберігатися.
8. П’ять доступів: admin (повний), service (каса + дві видачі), cash, bar, delivery. Права перевіряються сервером; ключі персоналу відкликаються, ключ власника зберігається. Не розширюйте права лише зміною UI.
9. Каса: звичайний тап додає позицію, утримання 300 мс зменшує кількість. Утримання рядка в кошику 300 мс змінює ціну; 400 мс на підсумку — подарунок. Свайп вліво відкриває замовлення, вправо — меню, лише коли каса має вкладки (до 999 px). Вертикальний скрол, поля, кнопки, довгі натискання, системний жест з краю та кілька пальців не повинні конфліктувати.
10. Усі анімації мають прибирання тимчасових елементів і підтримку prefers-reduced-motion. Не додавайте вкладені анімації при першому прихованому рендері, постійні will-change чи анімацію великих тіней.

## Дані

Windows: %LOCALAPPDATA%/MiniCafe. Android: внутрішній каталог застосунку. Зберігання — JSON, історична SQLite Windows переноситься автоматично зі збереженням оригіналу. Перехід на іншу БД не потрібен без окремої задачі. Резервна копія з меню, фото й замовленнями — окремий JSON, її немає в цьому архіві.

Базове меню: 8 напоїв по 50 грн з фото у work/android/assets/default-menu. Зміни користувача мають пріоритет; для цін використовується звичайний редактор. Редактор приховує чернетку кнопкою назад, а не стирає її.

## Відтворення середовища Windows

Сам код, Java-бібліотеки, шрифт PDF з ліцензією, базові фото та lock-файли входять в архів. Python, Node, JDK та Android SDK встановлюються окремо, їхні багатосотмегабайтні дистрибутиви не включені.

Потрібні Python 3.10+ із Tkinter (перевірено 3.12.14), Node 22.13+, JDK 17, Android SDK platform 35 та build-tools 35.0.0. SDK можна встановити Android Studio/SDK Manager. Прийняття SDK-ліцензій виконує власник середовища. Робочі локальні шляхи: work/android-tools/jdk/<JDK17>, work/android-tools/sdk; альтернативи — JAVA_HOME та ANDROID_HOME.

З кореня розпакованого архіву, у PowerShell (крапка на початку залишає налаштування середовища в поточній сесії):

```powershell
. .\work\scripts\setup_dev.ps1 -PythonExe python -JdkHome 'C:\Tools\jdk-17' -SdkHome 'C:\Tools\android-sdk'
python -X utf8 work/scripts/checks.py
```

setup_dev.ps1 ставить Python/npm-залежності та браузери Chromium/WebKit, задає PLAYWRIGHT_MODULE/CHROME_EXECUTABLE. Для наявного середовища можна встановити залежності вручну через requirements.txt, npm ci в work/tooling та Playwright CLI. Вбудований шрифт PDF обов’язковий: без нього старі версії падали під час старту сервера.

Збірка окремо:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File work/android/build.ps1 -PythonExe python
powershell -NoProfile -ExecutionPolicy Bypass -File work/scripts/build_desktop.ps1 -PythonExe python
python -X utf8 work/scripts/release.py --version 3.36
```

Повний checks.py збирає APK/EXE, запускає Java-набори, API на обох серверах, міграцію SQLite, Tk/QR, браузерні сценарії та запуск готового EXE. --skip-build/--skip-ui призначені для проміжних перевірок й не замінюють випуск. APK збирається без Gradle: aapt2, javac, d8, zipalign, apksigner. При наступному релізі збільшуйте versionName і versionCode у AndroidManifest.xml та назву версії Windows, оновлюйте звіт і контекст.

## Підпис APK — зберігати окремо

Для оновлення поверх встановленої програми потрібен ОРИГІНАЛЬНИЙ work/android/minicafe-signing.jks та паролі. Їх навмисно немає в архіві вихідного коду. Вони залишаються в попередньому робочому каталозі. Власнику потрібно зберегти їх окремою приватною резервною копією. Не публікуйте їх разом із вихідним кодом.

Паролі беруться з MINICAFE_STORE_PASSWORD / MINICAFE_KEY_PASSWORD або приватного work/android/signing.local.json. Відбиток очікуваного сертифіката є у work/android/signing-cert.sha256. Скрипт не створює новий ключ автоматично. Без оригінального підпису можна редагувати код і збирати Windows; сумісне APK-оновлення потребує відновлення ключа. Не радьте видаляти застосунок для обходу підпису: це може стерти робочі дані.

## Межі перевірки і продовження

Playwright перевіряє Chrome/Chromium та WebKit, телефонні/планшетні розміри й симуляцію JS-прапорця WebView. Це не емулятор Android. Нативні екрани перевірені компіляцією; анімації, камера, системні жести й фонова служба потребують перевірки на фізичному телефоні. Не стверджуйте протилежного без нового запуску на пристрої.

Прочитайте PROJECT-CONTEXT.json, потім нове завдання користувача. Збережіть сумісність даних і ключів, змінюйте канонічні джерела, виконайте відповідні перевірки, зберіть готовий APK/EXE та новий архів. У README.md є історія змін. Архів не містить робочих замовлень, паролів, персональних ключів чи старих каталогів збірки. SOURCE-FILES-SHA256.json дозволяє перевірити, що розпаковані вихідні файли не пошкоджені.
