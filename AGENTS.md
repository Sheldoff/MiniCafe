# MiniCafe — правила для будь-якого AI-помічника

Спочатку прочитай START-HERE-UA.md, PROJECT-CONTEXT.json і COLLABORATION-UA.md.
Пріоритетна політика напрямів: docs/PROJECT-TRACKS-UA.md.
Активні напрями: локальний Android і онлайн Cloudflare. Windows заморожений на
3.36 (archive/windows-3.36, реліз v3.36); не змінюй work/cafe/app.py,
work/cafe/desktop_engine.py, work/cafe/requirements.txt, work/desktop/ або
work/scripts/build_desktop.ps1, не збирай/не тестуй EXE без нового прохання власника.
work/cafe/frontend_build.py залишається активним спільним збирачем UI.
Cloudflare-напрям: apps/online/DEPLOY-UA.md. Керування захищено Telegram OIDC;
гості бачать «Меню формується». Не повертати відкритий admin API або
PUBLIC_TEST_MODE. Не публікувати приватні дані чи OAuth-токени.
Тести API онлайн запускаються тільки проти локальної одноразової D1.
Не запускати масові тести/restore проти публічного сервера користувача.
Це реальний застосунок з Android APK, Windows EXE та спільним вебінтерфейсом.

- Канонічні джерела UI: work/frontend; не редагуй згенерований index.html.
- Зберігай сумісність робочих даних, історії, доступів і API Android/Windows.
- Не використовуй базу користувача для тестів. Не перезаписуй меню базовим.
- Гроші — цілі копійки; правила подарунків/сесій/витрат описані в START-HERE-UA.md.
- Сервер перевіряє всі дозволи, клієнтський маршрут не підвищує права.
- Ключ підпису APK та паролі приватні. Вони передаються власником окремо,
  не потрапляють у коміти, журнали, issue, pull request чи артефакти.
  Не створюй новий ключ замість оригінального для оновлення застосунку.
- Працюй в окремій гілці task/<коротка-назва>. Перед роботою перевір git status,
  отримай актуальні зміни. Не стирай незакомічені правки іншого помічника.
- Не force-push main і не використовуй reset --hard/clean для «синхронізації».
- Фіксуй пов’язані зміни невеликими комітами, відправляй гілку, відкривай PR.
  Об’єднуй після перевірки відповідно до дозволу власника.
- Перевіряй змінене. Повний реліз потребує work/scripts/checks.py без skip.
  Не стверджуй, що перевірив фізичний Android/iPhone, якщо їх не використовував.
- Перед релізом узгодь версії та онови контекст і документацію.
- Якщо працюєш над частиною задачі, у PR опиши зміну, перевірки та обмеження.

Не делегуй роботу субагентам без явного прохання користувача.
